# Полевой журнал

![Полевой журнал — обследования объектов на iPhone и iPad](docs/preview.png)

Нативный журнал обследований: объект, инспектор, контрольные точки, замечания и фотографии в одной записи. Сценарий рассчитан на работу на объекте без постоянной связи и последующую передачу отчёта.

**Статус: исходники 0.1.0-rc.1 на проверке. iOS-приложение не собрано и не запускалось; шесть XCTest не выполнены.** На Windows проверен один комплексный HTTP-тест сервера обмена. Для native-проверок нужен Mac с Xcode.

Графическое превью выше — обложка репозитория, а не скриншот запущенного iOS-приложения.

## Что реализовано в исходниках

Для инспектора или сотрудника эксплуатации предусмотрен следующий маршрут: создать обследование, пройти пункты, зафиксировать замечания и подготовить переносимый результат.

- Обследования с названием, местом и инспектором; поиск и архив.
- Изменяемый чеклист, состояния пунктов, заметки и сводка выполнения.
- Выбор фотографий из библиотеки и код интеграции камеры; уменьшение изображения до 1800 px по большей стороне, JPEG и подписи.
- Текстовый отчёт и JSON-копия с фотографиями; импорт с объединением записей.
- Локальное файловое сохранение и одна предыдущая читаемая копия для восстановления.
- Опциональная отправка известных устройству изменённых записей на собственный сервер; выбор серверной версии или сохранение обеих при конфликте.

Эти возможности описывают код и проектируемый сценарий. Камеру, жизненный цикл приложения и поведение UI ещё нужно проверить на Apple-платформе.

## Собрать на Mac

Нужны **Swift 6+, Xcode с iOS 17+ SDK и XcodeGen**. Команды выполняются из корня репозитория.

```sh
brew install xcodegen
swift test
xcodegen generate
open PolevoyJournal.xcodeproj
```

В Xcode выберите схему **PolevoyJournal** и iPhone Simulator. Для собственного iPhone настройте Signing Team и bundle identifier. Облачные API-ключи не нужны.

Команда сборки для симулятора без подписи:

```sh
xcodebuild -project PolevoyJournal.xcodeproj -scheme PolevoyJournal -sdk iphonesimulator CODE_SIGNING_ALLOWED=NO build
```

Сама конфигурация Debug и эти команды пока не проверены на Mac. После успешной сборки следующий ручной сценарий: создать обследование, изменить чеклист, добавить фото из Photos, подготовить отчёт и JSON, перезапустить приложение и проверить восстановление. Камеру нужно проверять на физическом устройстве.

## Сервер обмена

Node.js **22+**, внешних npm-зависимостей нет. Сервер можно запустить независимо от iOS-приложения.

Mac / Linux, zsh или bash:

```sh
JOURNAL_TOKEN='replace-with-a-long-random-local-token' npm run sync
```

Windows, PowerShell:

```powershell
$env:JOURNAL_TOKEN='replace-with-a-long-random-local-token'
npm run sync
```

Замените пример своим случайным токеном длиной не меньше 16 символов. По умолчанию сервер слушает **127.0.0.1:4420** и сохраняет данные в `sync-data`.

| Маршрут               | Назначение                              |
| --------------------- | --------------------------------------- |
| `GET /health`         | Проверка доступности процесса           |
| `GET /records/{UUID}` | Получение конкретной записи             |
| `PUT /records/{UUID}` | Запись с `If-Match` и `Idempotency-Key` |

В настройках приложения задаются адрес и Bearer-токен. Для Simulator на том же Mac используется `http://127.0.0.1:4420`. Debug ссылается на `Configuration/LocalPreview.plist` с `NSAllowsLocalNetworking`; Release оставляет стандартную ATS-конфигурацию. Клиент разрешает HTTP только для loopback. Этот путь также требует проверки на Mac.

Для физического телефона нужен настроенный вами HTTPS reverse proxy. Локальный HTTP-сервер не следует публиковать напрямую. Общий токен не заменяет пользователей, роли и модель доступа публичного сервиса.

## Данные и архитектура

| Слой                | Ответственность                                                          |
| ------------------- | ------------------------------------------------------------------------ |
| `App`               | SwiftUI, PhotosUI, MainActor store и сценарии пользователя               |
| `JournalCore`       | Codable/Sendable-модели, валидация, actor хранилища, URLSession-клиент   |
| Локальное хранилище | JSON в Application Support, атомарная замена и предыдущая копия          |
| `sync`              | Node.js HTTP API, общий токен, версии, идемпотентность и дисковые записи |

Локальный журнал — основной рабочий набор. Обмен отправляет известные устройству изменённые записи; автоматического обнаружения новых записей с других устройств пока нет. Полный набор можно передавать JSON-копией.

Локальная revision и последняя подтверждённая remoteRevision разделены. Запрос передаёт базовую версию, чтобы сервер не перезаписывал чужую правку. Повтор распознаётся по ключу идемпотентности и содержимому. Детали гонок между await, сохранения и конфликтов — в [архитектуре](ARCHITECTURE.md).

Токен хранится только в памяти приложения и не включается в резервные копии. JSON с фотографиями и серверные данные не шифруются средствами проекта. Предыдущая локальная копия не заменяет backup вне устройства.

Лимиты: до 1000 обследований в копии, 200 пунктов и 30 фотографий на запись; до 5 МБ на фотографию и 100 МБ на импорт. Сохранность при потере устройства зависит от отдельных резервных копий.

## Проверка готовности

| Проверка                                   | Результат                                         |
| ------------------------------------------ | ------------------------------------------------- |
| `npm run test:sync`                        | **Пройден один комплексный HTTP-тест** на Windows |
| `swift test`                               | Написано 6 XCTest; **не запускались**             |
| iOS Simulator build                        | **Не выполнялся**                                 |
| Native UI, камера, VoiceOver, Dynamic Type | **Не проверены**                                  |

HTTP-сценарий проверяет авторизацию, повтор запроса, коллизию ключа, конфликт версии, запись на диск и рестарт сервера. Его успех не подтверждает сборку и работу iOS-клиента.

Workflow [apple-checks.yml](.github/workflows/apple-checks.yml) описывает Swift-тесты и сборку для симулятора. Наличие файла не означает успешного запуска CI. До Mac-проверок проект остаётся на стадии «Проверка».
